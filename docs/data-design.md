# データ設計書:Trello風タスク管理アプリ

作成日:2026-10-20 / 作成者:futa / 版数:0.2 / 状態:たたき台(2026-10-25 列名変更、並び順 position を追加)
関連文書:[要件定義書](requirements.md)、[画面設計書](screen-design.md)

## 1. データ設計の方針

- 実際のDBを使って運用する(バックエンドを作る想定)。利用者は1人で、マルチユーザー対応はしない。
- この文書は、ER図、テーブル構成、制約、インデックスを、**論理設計**(何を持つか)の範囲でまとめたもの。データ型やSQLの書き方などの**物理設計**は、技術選定でDBを決めた後に行う。
- ボードとユーザーはエンティティにしない(ボードは1つだけ、ログインなしのため)。

## 2. ER図

```mermaid
erDiagram
    COLUMNS ||--o{ CARDS : "含む"

    COLUMNS {
        int id PK
        string name "列名(未着手 / 作業中 / 完了)"
        int display_order "列の表示順(左から1,2,3)"
    }

    CARDS {
        int id PK
        int column_id FK "属する列"
        string title "タイトル(必須)"
        string description "説明文(任意)"
        string priority "優先度(高・中・低)"
        date due_date "期限(任意)"
        int position "列の中での並び順(小さいほど上)"
        datetime placed_at "列に置かれた日時(記録用)"
        datetime created_at "作成日時"
        datetime updated_at "更新日時"
    }
```

### 読み方

- `COLUMNS ||--o{ CARDS`:1つの列(COLUMNS)に、カード(CARDS)が0枚以上ある。カードは必ず1つの列に属する(1対多)。
- PK は主キー(1件を特定する項目)、FK は外部キー(他のテーブルの1件を指す項目)。

## 3. エンティティ一覧

| エンティティ | 意味 | 件数の目安 |
|---|---|---|
| COLUMNS(列) | 未着手 / 作業中 / 完了 の縦の列 | 3件(固定) |
| CARDS(カード) | 1つのタスク | 全体で200枚まで(NF-01) |

## 4. テーブル構成(項目定義)

### 4.1 COLUMNS(列)

| 項目名 | 論理名 | 型(論理) | 必須 | 備考 |
|---|---|---|---|---|
| id | 列ID | 整数 | 必須 | 主キー |
| name | 列名 | 文字 | 必須 | 未着手 / 作業中 / 完了 |
| display_order | 表示順 | 整数 | 必須 | 左から 1、2、3 |

初期データ(最初から入れておく3件):

| id | name | display_order |
|---|---|---|
| 1 | 未着手 | 1 |
| 2 | 作業中 | 2 |
| 3 | 完了 | 3 |

### 4.2 CARDS(カード)

| 項目名 | 論理名 | 型(論理) | 必須 | 上限 | 備考 |
|---|---|---|---|---|---|
| id | カードID | 整数 | 必須 | - | 主キー |
| column_id | 列ID | 整数 | 必須 | - | 外部キー(COLUMNS.id) |
| title | タイトル | 文字 | 必須 | 50文字 | 空は不可 |
| description | 説明文 | 文字 | 任意 | 500文字 | 改行可 |
| priority | 優先度 | 文字 | 必須 | - | 高・中・低のいずれか。追加時の初期値は「中」 |
| due_date | 期限 | 日付 | 任意 | - | 期限なしは空 |
| position | 列内の並び順 | 整数 | 必須 | - | 小さいほど上に表示する。カード追加・列の移動の時は一番上の値、「並べ替えモード」の完了時は列内を 1、2、3… に振り直す(2026-10-25 追加) |
| placed_at | 列に置かれた日時 | 日時 | 必須 | - | 作成時と、別の列へ移動した時に更新する。記録用で、並び順には使わない(2026-10-25 変更。変更前は並び順に使っていた) |
| created_at | 作成日時 | 日時 | 必須 | - | カードを作った日時 |
| updated_at | 更新日時 | 日時 | 必須 | - | 編集または移動した日時 |

## 5. 業務ルール(データの扱い)

### 5.1 表示順

- 列の中では、`position` が小さい順(昇順)に上から並べる。同じ値の場合は `id` が大きい順にする。
- 列は `display_order` の順に左から並べる。
- 編集しても `position` は変わらないので、編集したカードの位置は動かない。
- 「優先度順」「期限順」(F-10)は画面の表示だけの並べ替えで、`position` は変えない。保存済みの並びは `position` のまま残る。
- 変更の経緯: 2026-10-25 より前は `placed_at` の新しい順で並べていた。「並べ替えモード」で好きな順に並べて保存するため、並び順専用の `position` に変更した。

### 5.2 操作ごとのデータの動き

| 操作 | ユースケース | 動き |
|---|---|---|
| カード追加 | UC-02 | `column_id` を未着手(1)にして新規作成。`position` は未着手列の最小値より小さい値にする(一番上に入る)。`placed_at`、`created_at`、`updated_at` に現在日時を入れる |
| カード編集 | UC-03 | title、description、priority、due_date を更新し、`updated_at` を現在日時にする。`placed_at`、`position`、`column_id` は変えない |
| カード移動 | UC-04 | `column_id` を移動先の列にし、`position` を移動先の列の最小値より小さい値にする(移動先の列の一番上に入る)。`placed_at` と `updated_at` を現在日時にする |
| カード削除 | UC-05 | カードを削除する。復元はしない |
| 並べ替えの確定 | UC-06 | 「並べ替えモード」の完了時に、その列のカードの `position` を、画面の上から 1、2、3… に振り直し、`updated_at` を現在日時にする。`column_id` と `placed_at` は変えない。「優先度順」「期限順」はデータを変えない |
| ボード表示 | UC-01 | 全カードを列ごとに、5.1 の順で取り出す |

### 5.3 期限切れの判定

- 期限(`due_date`)が今日より前(昨日以前)なら期限切れとする。期限が今日の場合と、期限が空の場合は期限切れにしない(F-08)。

## 6. 画面項目との対応

| 画面の項目 | データの項目 |
|---|---|
| 列見出しの列名 | COLUMNS.name |
| 列見出しのカード枚数 | その列のカード数(CARDS を column_id で数える) |
| カードのタイトル | CARDS.title |
| カードの優先度の色 | CARDS.priority |
| カードの期限 | CARDS.due_date |
| S-02 の説明文 | CARDS.description |

## 7. 制約

データの正しさを守るための決まり。DB製品が決まる前なので、ここでは「何を守るか」を書き、書き方(SQL)は物理設計で決める。

| 対象 | 制約 | 種類 | 理由 |
|---|---|---|---|
| COLUMNS.id、CARDS.id | 重複しない | 主キー | 1件を特定するため |
| COLUMNS.name | 空にできない | 必須(NOT NULL) | 列名のない列は作らない |
| COLUMNS.display_order | 空にできない | 必須(NOT NULL) | 並び順が決まらなくなるため |
| CARDS.column_id | COLUMNS.id にある値のみ。空にできない | 外部キー、必須 | カードは必ず1つの列に属する |
| CARDS.title | 空にできない。50文字以内 | 必須(NOT NULL)、長さ | F-02、UC-02 の例外フロー |
| CARDS.description | 500文字以内 | 長さ | 入力上限(2章) |
| CARDS.priority | 「高」「中」「低」のいずれか。空にできない | 値の限定、必須 | F-07 の色分けに使う |
| CARDS.position | 空にできない | 必須(NOT NULL) | 列内の並び順(5.1)が決まらなくなるため |
| CARDS.placed_at、created_at、updated_at | 空にできない | 必須(NOT NULL) | 履歴に使う |

- 列(COLUMNS)に、カードが残ったままの削除はしない(列は3件固定で、削除する機能もない)。

## 8. インデックス(索引)

本の索引のように、DBが目的のデータを早く探すための仕組み。

| 対象 | 項目 | 目的 | 判断 |
|---|---|---|---|
| CARDS | `column_id`、`position`(昇順) | 列ごとにカードを保存済みの並びで取り出す(5.1、UC-01) | 張る候補。ただし200枚規模では張らなくても1秒以内(NF-02)に収まる見込み。技術選定のあとに決める |
| CARDS、COLUMNS | `id` | 1件の特定(編集・移動・削除) | 主キーに自動で付くため、追加は不要 |
