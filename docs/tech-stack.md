# 技術スタック候補:Trello風タスク管理アプリ

作成日:2026-10-24 / 作成者:futa / 版数:0.1 / 状態:候補の整理(未決定)
関連文書:[要件定義書](requirements.md)、[非機能要件](non-functional-requirements.md)、[データ設計書](data-design.md)

技術の選定は今後の課題で行う。ここには、現時点で決まっていることと、候補を書く。

## 1. 現時点で決まっていること(メモ)
- 実際のDBを使って運用し、バックエンドを作る想定(2026-10-20 決定)
- 利用者は1人で、マルチユーザー対応・ログインはしない
- 画面は1ページだけ(NF-08)
- 対応ブラウザは Chrome の最新版(Windows)、画面幅は1280px以上(NF-05、NF-06)
- カードを列の間でドラッグして移動できること(F-04)
- ER図は Mermaid 記法で書く(2026-10-20 決定)
- 想定カード枚数は200枚まで(NF-01)。大量データ向けの技術は不要

## 2. 候補
### 2.1 フロントエンド(画面)
| 候補 | 特徴 |
|---|---|
| HTML + CSS + JavaScript(素のまま) | 学習しやすく、追加の道具が要らない。ドラッグは標準の Drag and Drop API で作れる |
| React など | 画面の部品化がしやすい。学習量と道具(ビルド環境)が増える |

### 2.2 バックエンド(サーバー側)
| 候補 | 特徴 |
|---|---|
| Node.js(Express など) | フロントと同じ JavaScript で書ける |
| Python(FastAPI / Flask など) | 書き方が読みやすく、AI関連の学習とつなげやすい |

### 2.3 データベース
| 候補 | 特徴 |
|---|---|
| SQLite | ファイル1つで動き、インストール不要。1人利用・200枚規模に十分 |
| PostgreSQL / MySQL | 本格的なDB。サーバーを立てる手間があるが、実務に近い |
