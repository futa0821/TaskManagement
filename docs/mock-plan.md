# 画面モック(プロトタイプ)計画

作成日:2026-10-24 / 更新日:2026-10-25 / 作成者:futa
関連文書:[画面設計書](screen-design.md)、[機能要件](functional-requirements.md)、[データ設計書](data-design.md)

## 1. 目的
画面設計書の内容を、実際に動く画面で見て「完成イメージ」の認識合わせをする。
目的は**見た目と操作の流れの確認**。本実装(バックエンド・DB)の前段なので、HTML/CSS/JavaScript だけで作り、サーバーも外部ライブラリも使わない。技術スタック([tech-stack.md](tech-stack.md))の決定には影響させない。

## 2. 方針
- 置き場所: `mock/` フォルダ(`docs/` や将来の本実装と混ざらないように分ける)
- ファイル: `mock/index.html` / `mock/style.css` / `mock/script.js` の3つ。`index.html` をブラウザで開くだけで動く
- データ: JavaScript 内のサンプルデータのみ。**再読み込みで元に戻る**(F-06 の保存は、モックの対象外)
- 画面は S-01 ボード / S-02 入力モーダル / S-03 削除確認の3つ。1ページ構成(NF-08)、幅 1280px 以上が前提(NF-06)
- 見た目: 文字は游ゴシック、背景は薄めのグレー。タイトルは「Task Management」(白字、背景はボードで一番濃いグレー)。列の背景は、落ち着いた青系のスチールブルー(2026-10-25 決定。ボードの背景と見分けやすくするため、グレーから変更)。凝った装飾やアニメーションはしない

## 3. モックで確認できること(画面設計書との対応)
| 画面 | 内容 | 機能・設計書 |
|---|---|---|
| S-01 | 3列(未着手 / 作業中 / 完了)と、列見出しのカード枚数 | F-01 |
| S-01 | 未着手列の上だけに「+ カードを追加」ボタン | F-02、画面設計書 3章 |
| S-01 | カード:優先度の色(高=赤・中=黄・低=緑)、【高】【中】【低】の文字の色、タイトル、期限(M/D、なしは「なし」)、🗑ボタン。説明文は出さない | F-03、F-07 |
| S-01 | 期限が昨日以前なら期限の文字を赤(当日は赤にしない) | F-08 |
| S-01 | カードを別の列へドラッグ → 移動先の列の**一番上**に入る | F-04 |
| S-01 | 各列の「優先度順」「期限順」ボタン:押した列だけを一時的に並べ替える(保存しない)。選択中のボタンをもう一度押すと解除する | F-10、UC-06 |
| S-01 | 各列の「並べ替えモード」ボタン:モード中だけ、同じ列の中でドラッグして並べ替える。「並べ替え完了」で終える。モード中は優先度順・期限順ボタンと、別の列への移動が使えない | F-10、UC-06 |
| S-02 | 追加・編集共用モーダル:タイトル(必須・50字)、説明文(500字)、優先度(初期値「中」)、期限、キャンセル/保存 | F-02、F-09 |
| S-02 | タイトルが空のまま保存 → M-01「タイトルを入力してください」を表示し、モーダルを開いたままにする | 画面設計書 6.2、7章 |
| S-03 | 「本当に削除しますか?」[やめる][削除する]。カードの🗑クリックでは編集モーダルは開かない | F-05 |

- 列内の並びは、データ設計書の `position`(小さい順)に対応する。サンプルデータは、各列に優先度・期限がばらばらのカードを入れ、並べ替えを試せるようにしてある。
- 期限切れの確認が日付に依存しないよう、サンプルの期限は「今日からの相対日数」で作る。

## 4. 対象外(モックでは作らない)
データの保存(F-06)、エラーメッセージ M-03・M-04、サーバーとの通信、画面幅 1280px 未満への対応、キーボードでのドラッグ操作、テストの自動化。

## 5. 進め方
1. 画面設計書をもとに、モックを作る
2. ブラウザで動かし、見た目と操作を確認する
3. 気になる点を洗い出し、直すべき点は先に設計書を直す(設計書とモックの内容を一致させる)
4. 修正が完了したら、まとめてコミット・プッシュする

## 6. 確認方法
`mock/index.html` をブラウザで開いて、次を確認する。
1. 列名が「未着手 / 作業中 / 完了」で、列見出しの枚数がカード数と一致する
2. 追加ボタンは未着手列にだけあり、押すと入力モーダルが開く(優先度の初期値は「中」)
3. タイトルが空のまま保存すると M-01 が出てモーダルが残る。入力して保存すると、未着手の一番上にカードが入る
4. カードをクリックすると、現在の内容が入った編集モーダルが開く。保存してもカードの位置は変わらない
5. 🗑を押すと確認ダイアログだけが出る。「やめる」で変化なし、「削除する」でカードが消える
6. 通常時、カードを別の列へドラッグすると、移動先の一番上に入り、両列の枚数が更新される
7. 優先度の色(カードと【高】【中】【低】の文字)が、高=赤、中=黄、低=緑になっている。昨日以前の期限だけが赤い
8. 「優先度順」で高→中→低、「期限順」で期限の近い順(期限なしは最後)になる。他の列は変わらない。選択中のボタンをもう一度押すと元に戻る
9. 「並べ替えモード」中は、同じ列の中でドラッグして並べ替えられる。優先度順・期限順ボタンと、別の列への移動は使えない。「並べ替え完了」後も並びが残る
10. 文字が游ゴシック、背景が薄いグレーで表示される。列の背景が、青系(スチールブルー)で、ボードの背景と見分けられる
11. タイトルが白字の「Task Management」で、背景がボードの中で一番濃いグレーになっている
12. 再読み込みすると初期状態に戻る(想定どおり)
